# Reading the C++ firmware

Start with `main.cpp`: `setup()` runs once, and `loop()` repeatedly handles serial commands, Wi-Fi, weather results, screen updates, and sleep.

| File | Purpose |
|---|---|
| `main.cpp` | Coordinates the hardware and app; refresh timings are near the top; location comes from setup |
| `WeatherConfig.h` | OLED pins, size, and brightness |
| `WifiSetup.cpp` / `.h` | Local Wi-Fi setup page, saved credentials, and reconnection |
| `WeatherClient.cpp` / `.h` | Downloads and validates weather using HTTPS |
| `WeatherData.h` | Weather fields and freshness checks |
| `SceneRotation.h` | Shuffles each weather group without repeating scenes |
| `WeatherRenderer.h` | Draws the animated clouds and weather effects |
| `LandscapeArt.h` | Stored pixel artwork; these numbers are image data, not program logic |

The network request runs in a separate FreeRTOS task so it does not freeze the setup page. A queue hands its result back to the main loop. The processor uses light sleep, which preserves memory and leaves the OLED image visible.

See the root README for wiring, dependencies, build commands, and setup. The `.ino` file is only an Arduino build entry; implementation is in C++.

The optional `../image_to_array.py` helper converts pictures into C++ bitmap declarations on a computer. It is not part of the Arduino build. See the root README for usage and storage format.

## Custom image details

To use the picture in the existing weather rotation, replace one image's 1,024-byte initializer inside `kLandscapeArt` in `LandscapeArt.h` with the generated bytes. Keep the existing array size and entry order. Static image indices are: Sun 0–17, Moon 18–35, Partly cloudy 36–53, Cloudy 54–71, Rain 72–88, Fog 89–105, Snow 106–122, Thunderstorm 123–139. Rebuild and upload after editing.

Options: `block_size=2` (1–10), `threshold=128` (0–255), `dither=True`, `invert=False`, and `name="kCustomArtwork"`. Images are orientation-corrected and center-cropped to 128×64; transparent areas become black. Animated files use their first frame.

The converter adapts [edge-aware-pixel-art](https://github.com/bam-project/edge-aware-pixel-art): Gaussian blur and Canny detect edges, then each block uses its median color or the mean of dark pixels when the dark/edge fractions pass the source thresholds. The OLED step converts the result to on/off pixels, optionally using dotted shading.

Each image contains 8,192 one-bit pixels packed into **1,024 bytes**, left to right and top to bottom. Each byte holds eight horizontal pixels, most significant bit first; 1 lights a pixel and 0 leaves it off. Built-in arrays live in program flash, not as PNG/JPEG files. The eight procedural scenes are drawn by code.
